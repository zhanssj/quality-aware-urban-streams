# Разбор аудита AirQualityBench и дополнительная диагностика PM2.5

## Что уже проверено здесь

Из пользовательского `audit_results.zip` прочитаны все четыре файла: `report.md`, `summary.json`, `pollutant_year_summary.csv`, `pm25_station_year.csv`. Пересчитаны агрегаты по 18 600 строкам «станция-год», сверены суммы, состав станций и пороги покрытия между CSV и JSON. Исходные HDF5 в этой среде отсутствуют, повторного сканирования реальных массивов здесь не было.

- `review_ru.md`: выводы и ограничения.
- `derived_findings.json`: пересчитанные показатели и контрольные суммы входных отчётов.
- `training_candidates_669.csv`: диагностическая группа из 669 станций с покрытием PM2.5 не ниже 80% в 2023 году. Отбор использует только тренировочный период, не 2024/2025. Это не финальная выборка статьи.
- `source_audit/`: неизменённые файлы присланного аудита.
- `review_from_reports.py`: воспроизводит расчёты по отчётам и формирует диагностическую группу.
- `deep_audit_pm25.py`: второй этап проверки реальных HDF5 на вашем компьютере.
- `test_deep_audit.py`: синтетические тесты второго этапа.

## Запуск в существующем проекте

Распакуйте архив в корень прежнего проекта. Структура должна выглядеть так:

```text
project/
├── .venv/
├── data/
│   ├── aq_compact_2021.h5
│   ├── aq_compact_2022.h5
│   ├── aq_compact_2023.h5
│   ├── aq_compact_2024.h5
│   └── aq_compact_2025.h5
└── airqualitybench_review/
    ├── deep_audit_pm25.py
    ├── training_candidates_669.csv
    └── ...
```

Из корня `project` в PowerShell:

```powershell
.\.venv\Scripts\python.exe .\airqualitybench_review\deep_audit_pm25.py --data .\data --out .\audit_deep
```

Linux:

```bash
.venv/bin/python airqualitybench_review/deep_audit_pm25.py --data data --out audit_deep
```

Нужны только уже установленные `numpy` и `h5py`. Данные повторно скачивать не требуется. Исходные файлы открываются только для чтения; заполнение пропусков, очистка, обучение моделей и коррекция меток времени не выполняются.

Программа обрабатывает один год и один показатель за раз. На один год исходная матрица PM2.5 занимает около 130 МБ плюс маски, временные массивы и отчёты. Потребление памяти будет выше этого числа, ориентировочно несколько сотен мегабайт; фактический пик на реальных файлах здесь не измерен.

Для пробного запуска только ранних лет:

```powershell
.\.venv\Scripts\python.exe .\airqualitybench_review\deep_audit_pm25.py --data .\data --out .\audit_deep_early --years 2021 2022 2023
```

## Результат

`audit_deep/audit_deep_results.zip` содержит:

| Файл | Что проверяет |
|---|---|
| `coverage_by_step.csv` | Число доступных станций на каждом индексе; общий и фиксированный тренировочный состав |
| `low_coverage_intervals.csv` | Интервалы с покрытием менее 10% и 50% в фиксированной группе |
| `repeated_internal_gaps.csv` | До 100 самых часто повторяющихся точных внутренних интервалов пропусков длиной от 24 шагов за каждый год |
| `station_longest_gaps.csv` | До трёх самых длинных пропусков каждой станции за каждый год, с типом и позициями |
| `station_continuity.csv` | Наблюдаемые соседние пары и полностью наблюдаемые окна 6/24 прошлых значений плюс цель |
| `value_distributions.csv` | Точные квантили отдельно для mask=1 и конечных чисел при mask=0 |
| `extreme_examples.csv` | До 10 крупнейших значений каждой из двух групп на год с ID станции и индексом |
| `deep_summary.json` | Сводка, контрольная сумма диагностической группы и ограничения |

Индексы строк нулевые. Интервалы записаны как `[start_row_inclusive, stop_row_exclusive)`: начальная строка включена, конечная не включена. Разрывы и непрерывные окна рассчитываются отдельно внутри каждого года, не через границы лет.

Число полных окон приводится для диагностики, а не как указание удалить все неполные окна из эксперимента. Как раз они нужны для нашей задачи.

2025 год анализируется только описательно. Его покрытие, распределения и ошибки будущих моделей нельзя использовать для подбора удобных станций или изменения правил эксперимента.

## Чего скрипт не сможет подтвердить

Даже совпадение интервалов у сотен станций не доказывает конкретную причину: нужно изучать источник и подготовку данных. В отчёте первого этапа у файлов нет временных массивов или атрибутов. Поэтому скрипт намеренно не создаёт календарные даты из имён файлов и не называет шаги часами.

Часовой пояс, единицы, источник масок, очистка значений и реальные моменты доставки сообщений требуют документации/кода формирования датасета. Диагностика чисел этого не заменяет.

## Проверки кода

В этой среде пройдены четыре теста нового скрипта на синтетическом HDF5: границы интервалов и окна, совпадающие пропуски/нулевые значения/NaN/маски, отклонение отсутствующей станции. Отдельный тест проверяет запуск CLI и целостность результирующего ZIP на синтетическом файле. Реальный HDF5 здесь не использовался.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s .\airqualitybench_review -p test_deep_audit.py -v
```

Пересчёт анализа исходного аудита:

```powershell
.\.venv\Scripts\python.exe .\airqualitybench_review\review_from_reports.py
```
