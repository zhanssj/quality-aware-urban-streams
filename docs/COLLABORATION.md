# Связка пользователя, ChatGPT и Codex

## Основной маршрут

Общий Git-репозиторий - источник постановки, кода, решений и небольших отчётов.
Codex работает локально рядом с уже скачанными HDF5. ChatGPT читает доступный remote по запросу пользователя и ревьюит зафиксированный commit/PR.
Доступ к GitHub в текущем диалоге проверен для аккаунта zhanssj. Это не означает, что новый проект уже создан или что доступ к нему был проверен.

Настроенный владельцем remote (проверен локально 2026-11-02): `https://github.com/zhanssj/quality-aware-urban-streams.git`.
Локальный main на момент начала T01: `6687db6`. Права Pro-чата на чтение этого репозитория в этой сессии не проверялись.
Другие GitLab-проекты переносить не требуется. Для существующего GitLab-проекта можно использовать доступный официальный GitLab plugin, но он зависит от workspace. В каталоге текущего сеанса он не найден; подключённым его не считаем. Дополнительные варианты интеграции могут быть доступны в каталоге пользователя.

## Что передаётся

Код, AGENTS.md, протокол, конкретная задача, test logs, конфигурации, небольшие метрики, указатель на артефакты и commit SHA.
Полные HDF5, секреты и тяжёлые prediction/model файлы в Git не попадают. При необходимости отдельного воспроизведения используются разрешённые локальные данные и зафиксированные хеши.

## Рабочий цикл

1. Пользователь назначает Codex одну задачу, например T01.
2. Codex читает репозиторные инструкции, создаёт локальную ветку, реализует и проверяет задачу.
3. Codex заполняет `handoffs/T01.md` и обновляет STATUS. Отправка ветки/PR в remote выполняется только с согласованными правами и разрешением.
4. Пользователь сообщает ChatGPT: repository, task, branch/PR, code_commit и расположение handoff.
5. ChatGPT читает код/изменения и evidence, а не только обещание агента. Результат: APPROVED / CHANGES_REQUESTED / BLOCKED с конкретными файлами и проверками.
6. Замечания сохраняются в `reviews/T01.md` либо передаются Codex одним сообщением. Только то, что явно передано или записано в доступный репозиторий, становится контекстом Codex.
7. После исправлений повторяем ревью; следующий task назначается отдельно.

ChatGPT не наблюдает за каждым push автоматически и не запустил здесь никакой фоновый процесс. AGENTS.md не является каналом сообщений и не переносит всю историю разговора.
В этом диалоге нет вызова, который управляет локальной Codex-сессией пользователя. GitHub-канал даёт доступ к сохранённым материалам, не управление компьютером.

## Когда remote неудобен

Codex формирует review_bundle.zip по whitelist: код или diff с необходимым контекстом, спецификация, handoff, тесты/логи, конфигурация, небольшие метрики, SHA256 manifest.
Без HDF5, .env, .git, auth.json, токенов, symlink targets, моделей и полных больших логов. Секреты проверяются до упаковки; это не гарантия отсутствия секретов, владелец проверяет архив.
При таком маршруте ChatGPT получает только снимок, а не текущую локальную папку.

## Уровни подтверждения

- READ: материалы прочитаны.
- EXECUTED: проверка действительно запущена и есть результат.
- REPRODUCED: результат повторён на указанном коде/входах/окружении.
Чтение лога Codex не равняется независимому повторению его эксперимента.

## Автоматизация позже

Официальные Codex SDK / app-server / codex exec позволяют строить управление задачами программно. Это отдельное приложение/CI, отдельные права, а не автоматическое подключение данного браузерного чата.
В текущий MVP такую оркестрацию не включаем. Никаких скриптов автослияния, широких токенов, отключения sandbox или прямого доступа к домашней машине ради handoff.
