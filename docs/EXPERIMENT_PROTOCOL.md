# Протокол эксперимента v0.2

Статус: проектный контракт для реализации, не результаты исследования.
Изменение разделения, сетки target, методов, критериев отбора и сценариев требует записи в DECISIONS.md до финального теста.

## 1. Данные и независимые состояния доступности

`source_valid = (mask == 1) & isfinite(value)`.
`effective_available = source_valid & delivered_by_cutoff & ~synthetically_dropped`.
Сохранять оригиналы неизменными. Скрытые числа не участвуют в заполнении, rolling, обучении или оценке.
Отдельно существует truth store: исходный PM2.5 и source_valid, доступный только конструктору обучающих labels/оценщику, но не online feature builder.
Причина недоступности из симулятора не является признаком модели.

## 2. Сетка и прогнозируемая величина

Первое внедрение использует индекс следующего шага. Пустые строки сохраняются; возраст и разрывы считаются по полной сетке.
Для replay предлагается конвенция завершённых интервалов:
- строка t представляет завершившийся интервал [t, t+1);
- origin = конец интервала t;
- target = значение следующего интервала t+1;
- simulated_arrival_time(t) = interval_end(t) + delay(t);
- cutoff = origin + wait;
- допустимые входы: interval_end <= origin и arrival <= cutoff;
- target и все записи целевого интервала запрещены как входы, даже если ошибочно имеют ранний arrival.

Пример при условном шаге 60 минут: историю до [12:00,13:00) используем для цели [13:00,14:00); выдача 13:00, 13:05, 13:15. Последние две выдачи уже внутри целевого интервала. Не называть их полноценным прогнозом с 60-минутным упреждением; сохранять 60/55/45 минут до его конца.
Это симуляционная конвенция. Реальные времена поступления отсутствуют. Календарную/физическую семантику HDF5 не объявлять установленной без документального подтверждения.
В первом прототипе часовые/сезонные признаки отключены, пока их привязка не подтверждена. Можно использовать позиции шагов без выдуманного часового пояса.

## 3. Разделение и выбор станций

Train 2021–2023, validation 2024, test 2025. Разделять по target, не по origin. На границах годов не допускать target 2024 в train.
Validation может использовать реально доступную историю до своей границы; test может использовать предшествующую историю после freeze. Это не разрешает fit на этих периодах.
2025 уже просмотрен описательно в аудитах. Честная формулировка: удержанный период оценки моделей, не полностью слепой набор.
Дополнительный отбор станций только по train/метаданным, не по точности или полноте validation/test.
Существующие 669 использовать как кандидатов. Для первого bounded прогона: 32 станции из списка, детерминированно выбранные с сохранением seed/списка. Выбор не оптимизировать по результатам.
Исходный benchmark ретроспективно отбирал сеть; эксперимент представляется как работа с фиксированной сетью.
До публикационных агрегированных метрик подтвердить совместимость единиц выбранной группы. Не смешивать неустановленные единицы и не подписывать их автоматически µg/m³.
Для технического прототипа можно считать диагностические ошибки в единицах файла с явным `units_verified=false`; не интерпретировать как физический результат статьи.

## 4. Признаки и заполнение

Общие признаки: лаги PM2.5 1,2,3,6,12,24 относительно target; среднее и разброс по последним 6/24 позициям.
Правило по умолчанию: forward-fill только из реально доступного прошлого; при отсутствии истории - медиана, fitted только на train.
Медиана конкретной станции берётся только из её train; при отсутствии использовать train-only global fallback и отдельный флаг отсутствия истории. Это допустимо для публикационных объединённых моделей только после проверки единиц.
Конкретно документировать, считаются ли rolling по заполненному ряду; в основном сравнении считать по одному и тому же причинно заполненному ряду. Доли пропусков считаются по исходной доступности, а не после заполнения.
Дополнительные quality-признаки: observed masks лагов, возраст последнего доступного наблюдения, missing_ratio_6/24, текущая длина последовательной недоступности, has_history.
Возраст зависит от event/interval time, а не от порядкового номера доставки. Late событие не должно заменить более свежее как last-known.
Никакой bidirectional interpolation/backfill, центрированных окон, нормализации по всем годам.
Метаданные station_id нужны для группировки, но не превращаются в произвольное непрерывное число для модели. В первой глобальной модели station_id не является predictor. Добавление категориального представления - отдельное решение с проверкой памяти.
При проверке причинности fitted training state заморожен: изменение входных событий после cutoff не должно менять признаки ранее выданного прогноза.

## 5. Модели

Persistence: последнее доступное PM2.5; при полном отсутствии истории - тот же train-only fallback, с явным флагом fallback.
Standard: фиксированная общая числовая feature pipeline + HistGradientBoostingRegressor.
Quality-aware: та же pipeline и модельное семейство, плюс quality features.
Общее ядро подготовки признаков, одинаковые sample IDs, origins, targets, конфигурация алгоритма и сценарии.
В основном сравнении общие гиперпараметры; подбор только на validation, затем фиксация. Отключить раннюю остановку со случайным внутренним validation split; временная validation внешняя.
Native-missing baseline с NaN - дополнительный контроль, если помещается в согласованный эксперимент.
Модель не обязана улучшаться: отрицательный/условный результат сохраняется, не корректируется подбором test.

## 6. Нарушения и воспроизведение

Первое сравнение T03 на исходной неполноте. В T04 deterministic random drop 5/10/20% среди source-valid входных измерений и блоки 6/24 шагов.
Для одиночных/групповых отключений сохранить duration, частоту, долю затронутых станций и фактическую потерю. Один и тот же общий календарь событий используется всеми моделями, а не новая маска на каждое окно.
Случайное сокрытие 10% доступных входов не значит 10% общей недоступности. Всегда записывать оба показателя.
Тренировочная смесь нарушений фиксируется до validation matrix; train/validation/test используют независимые seeds. Не дублировать clean окна непропорционально без зафиксированных весов.
T05: задержки 1–30 симуляционных минут у 10/30% сообщений и ожидание 0/5/15 минут. Синтетический час = 60 минут по выбранной конвенции, не доказательство реального timestamp.
Прогнозы запускаются по расписанию независимо от прихода сообщений. Выданный прогноз неизменяем.
После восстановления доставки новые данные используются только в последующих прогнозах, не переписывают старые результаты.
Для baseline после появления сценариев допускается первоначально frozen clean-trained evaluation; окончательное сравнение clean-trained и общей augmented-training смеси фиксируется в T06, не смешивается в одной таблице без меток.

## 7. Оценка

Сохранять все запланированные прогнозы, включая случаи без target; ошибки считать только по source-valid target.
Для сравнения использовать один список target IDs. Пропуски предсказаний показывать как снижение coverage; модель не получает преимущество молчаливым пропуском трудных примеров.
Основная MAE, дополнительная RMSE; pooled и macro-per-station после подтверждения совместимости единиц; отдельно разрывы, восстановление и обычные периоды.
Для 2022 глобальной пустоты нет истины внутри провала; оценить там точность по архиву невозможно. Контролируемые потери скрывают только inputs, а не truth оценщика.
Первичный pilot: 3 seeds. Итог: 5 заранее фиксированных seeds. Парные методы получают одинаковые нарушения. Seeds не считать новыми независимыми городами.
Неопределённость разности ошибок оценивать парным block bootstrap по временным блокам, сохраняя станции одного блока вместе; размер блока фиксировать до test. При неподтверждённой календарной оси использовать блоки шагов, не называть их неделями.
Ablation: Standard, +masks, +age, full quality на заранее выбранных validation сценариях.

## 8. Производительность

Реально измерять feature computation, inference и полный job latency; p50/p95, throughput, peak RSS, версии зависимостей, CPU, RAM, потоки, размер батча.
Warmup и измеряемые повторы разделены. Сравнения на одном оборудовании, workload и ресурсных ограничениях.
Simulated delay, policy wait и wall-clock processing latency - три разные величины. Их сумма с остатком до цели должна быть объяснена, не смешана.
Копирование станций/ускоренное воспроизведение допустимо только для нагрузки, не как увеличение независимой выборки точности.
Для статьи о latency Kafka не обязателен: kernel/job latency и policy waiting исследуются отдельно; end-to-end broker latency доступна только после T08.

## 9. Freeze и финальный тест

T06 фиксирует код, модель/параметры, признаки, список станций, единицы, временную конвенцию, seeds, сценарии, метрики и шаблоны таблиц.
Протокол test сохраняется как `protocol_freeze.json` с хешами; разрешение владельца отдельное, не придуманное агентом.
T07 открывает 2025 только после явного согласия. Баги после test исправляются прозрачно, результаты версионируются; никакой тайной повторной настройки по test.
Без подтверждённых единиц/семантики T07 может подготовить технический вывод, но публикационные физические утверждения остаются BLOCKED.
