## N1 - неблокирующее замечание: denominator coverage не сверяется с планом

Файл: src/aqstream/evaluation.py:13-14,54-55,87-90.
`scheduled` - число присутствующих строк CSV. API получает только CSV и не сравнивает
его sample IDs с заранее запланированной сеткой. Если файл завершён на границе строки
или из него удалены строки, он может пройти оценку с prediction_coverage=1.0.
Одинаковое число строк само по себе также не обнаружит замену ожидаемых ID неожиданными.

Независимое воспроизведение на трёх синтетических target:
- полный CSV: scheduled=3, predicted=3, coverage=1.0, MAE=2.0;
- удалена последняя строка: scheduled=2, predicted=2, coverage=1.0, MAE=1.5;
- реальный план в обоих случаях содержит три target.

Это доказательство ограниченности текущего evaluator, НЕ свидетельство потери строк
в опубликованном пилоте. Для пилота числа согласуются:
8784 * 32 = 281088 = 262904 scored + 18184 missing truth,
missing predictions=0 у всех методов по сохранённому JSON.

Доработка для B02:
1. Передавать план/контекст запуска: cohort, сетку target и идентичность run/scenario/wait.
2. Сверять фактический набор ID с ожидаемым, а не только его размер.
3. В experiment runner проверять полноту до объявления итогового PASS.
4. При отсутствующих/лишних ID - явный DataContractError или явно неуспешный результат;
   не называть долю конечных prediction среди имеющихся строк полнотой расписания.
5. Не смешивать разные сценарии/ожидания в одной метрике без явного группирования.
6. Тесты: полный CSV, удалённая строка, замена ID с тем же count, дубликат, смешанные run/scenario.

Статус N1: deferred to B02, не блокирует принятие текущего B01.
Репродуктор: reproduce_coverage_gap.py. Его вывод: evidence/coverage_gap.json.

## Научная корректность проверенной реализации

- Forecast создаётся до observe(target); target не передаётся в model.predict.
- Fallback fitted только на train. Валидационная история обновляет наблюдения,
  но не fitted preprocessing state или модель. Это rolling one-step evaluation.
- Split назначается по target; первые validation примеры могут использовать прошлую train историю.
- Standard и Quality-aware используют общий блок, одинаковые train labels и параметры HGB.
- Early stopping выключен; случайный внутренний validation split не используется.
- Истинно отсутствующие labels не заполняются для fit/scoring.
- Сетка сохраняет пропуски; общий scored intersection используется всеми моделями.
- 2025 остаётся запрещён; сценарии доставки ещё не реализованы и не объявлены выполненными.

## Интерпретация сохранённого пилота

| Метод | MAE | RMSE |
|---|---:|---:|
| Persistence | 1.5499771784510274 | 3.9303319286056606 |
| Standard | 1.9085767341210202 | 4.026499848233516 |
| Quality-aware | 1.9022502283940146 | 4.026686198717474 |

Quality-aware уменьшает MAE относительно Standard на 0.0063265057, или 0.3314777%.
RMSE Quality-aware выше Standard на 0.0046281%. MAE Quality-aware выше Persistence
на 22.7276282%. Эти проценты пересчитаны из сохранённых метрик, не из исходных прогнозов.
Без парного анализа и оценки неопределённости нельзя объявить эффект статистически подтверждённым.

В пилоте нет требования, чтобы HGB выиграл. Проигрыш Persistence сам по себе не является багом.
Проверка не нашла подмены Persistence истинным текущим target. Причина преимущества Persistence
по одному JSON не установлена. Гипотезы о плавности ряда или недостаточной гибкости HGB
не следует записывать как установленный результат.

Объём fit - 62338 пригодных labels из 105120 запланированных subsampled строк.
train_stride=8 и max_iter=60 заданы до пилота. Это ограниченный baseline, не лучшая
достижимая конфигурация модели. Последовательный subsample имеет ограничение: при
24-позиционной периодичности индексы modulo 8 выбирают лишь три фазы modulo 24.
Это математическое свойство выборки, не доказательство реальных часов или сезонности набора.
Не менять текущий пилот задним числом; sensitivity/tuning допустимы как отдельно названные
validation эксперименты позднее, без 2025.

Все метрики diagnostic_only / file_units / units_verified=false.
Никаких физических, статистических или city-wide выводов это ревью не подтверждает.
Наблюдение B01 относится к естественной неполноте; устойчивость при добавленных
потерях и задержках ещё не проверена.
