# T05: Доставка, виртуальные часы и политика ожидания

Статус: TODO

Предусловия: T04 принят.

## Реализовать

Event time/interval end, arrival time, cutoff; дискретно-событийный replay без реального ожидания каждого исторического часа.
Прогнозы по расписанию для waits 0/5/15 минут и одной цели. Распределение задержек по конфигурации, начальные кандидаты 1–30 минут у 10/30% сообщений.
Inputs только из интервалов, завершённых до origin, и доставленных к cutoff. События целевого интервала исключены.
Детерминированное правило ties на cutoff: arrived<=cutoff видимо; порядок одинаков во всех методах.
Старые поздние сообщения не заменяют более новое last-known, но могут корректно обновить историю для будущих прогнозов.
Прогноз immutable после публикации. Получение сообщения не является условием запуска forecast.

## Тесты приёмки

Сообщение в cutoff+epsilon невидимо, в cutoff видно согласно контракту.
Дубликаты не меняют счётчики/историю. Arrival order не меняет результат на том же snapshot доступности.
Цель одинакова для waits; remaining lead сохраняется, не объявляется постоянным часом.
Позднее сообщение не переписывает уже выпущенный prediction.
Value интервала [12,13) не доступно до13 по симуляционной конвенции.

## Измерения

Сохранять simulated delay, policy wait и wall-clock computation отдельно. Не представлять симуляционную минуту как реально измеренную latency.
